# Validity Threats and Mitigations — Praxis Research Design

**Design:** Quasi-experimental, pre/post, single group (approved 2025-02-06).  
**Source:** Agent 02 (First_Run_Validity_Notes + Deep Dive); PI approved design.  
**Research questions:** See `03_Research_Methods/Research_Design/Methodology_Framework_v1.md`.

---

## Internal Validity

| Threat | Description | Mitigation |
|--------|-------------|------------|
| **History** | External events (e.g., new threats, policy change) between pre and post could explain change | Document timeline; note and control for known external events; sensitivity analysis excluding periods with known shocks |
| **Maturation** | Natural change in operators, tools, or environment over time | Fixed measurement window; same population and procedures at pre and post; baseline trend if data available |
| **Testing** | Pre-test or repeated measurement affects post scores | Use non-reactive measures where possible; separate pilot from main measurement; document any training or familiarization |
| **Instrumentation** | Change in how the outcome is measured (e.g., tool upgrade, log source change) | Hold instrumentation constant or measure and control for version; document all data collection details |
| **Selection** | Differences between groups (if multiple groups) or attrition | Define inclusion criteria; report attrition; if comparative, document selection and consider propensity or matching |

---

## External Validity

| Threat | Description | Mitigation |
|--------|-------------|------------|
| **Setting** | Results may not generalize beyond the study context | Describe setting, population, and artifact context; limit claims to “similar contexts”; avoid overgeneralization |
| **Population** | Sample may not represent broader population | Define eligibility; report demographics/context; state generalizability limits in limitations section |
| **Time** | Findings may be time-bound | Document study period and relevant temporal factors; note in limitations |

---

## Construct Validity

| Threat | Description | Mitigation |
|--------|-------------|------------|
| **Operationalization** | Measures may not fully capture constructs | Define constructs and operational definitions; align with SEAS 8410/8414 metrics; cite existing scales or standards where used |
| **Single method** | One source or method per construct | Triangulate where feasible (e.g., metric + qualitative note); document single-method limitation |
| **Expectancy** | PI or operator expectations bias measurement | Use objective metrics where possible; blind assessment if feasible; document procedures |

---

## Conclusion Validity

| Threat | Description | Mitigation |
|--------|-------------|------------|
| **Low power** | Sample size or effect size may preclude detection | Justify sample size (power analysis or feasibility); report effect sizes and CIs; avoid overclaiming null results |
| **Alpha / multiple testing** | Inflated Type I error with multiple tests | State alpha; adjust for multiple comparisons or pre-specify primary outcome; document all tests |
| **Assumption violation** | Statistical assumptions not met | Check and report (e.g., normality, independence); use robust methods if needed (Agent 07) |
